Curator

Sends your library to an LLM, asks what threads run through it, and builds the answers into ordered playlists surfaced as home screen rows.

Rows

Curator builds two kinds of row, and each is asked the same two questions: how big is a row, and how many rows. Every number below is also written into the prompt, so the model aims at what it will be judged by rather than having its answer quietly trimmed.

Keeping rows steady

The model coins largely different threads each run, so a row going missing once usually means the run phrased things differently rather than your taste having changed. Dropping it immediately makes the home screen flicker — the row vanishes and is back the next week. This waits that many runs before a row goes; it still goes eventually if it really has gone. 0 drops it immediately.

None of this touches Recommended for you — that playlist is ranked rather than curated, and its length is Length on the Home screen tab.

Condensed summaries

Overviews are about two thirds of every prompt, and the same text is re-sent on every run forever. This rewrites each long overview once into a short summary that keeps the feel of a title rather than its plot, and caches the result. After the first pass only new and rewritten items cost anything. Your library's own overviews are never modified — the short versions live only in Curator's data directory, so clearing them puts everything back exactly.

Tag consolidation

Scraped keyword lists run to about eighteen values an item and are mostly production trivia — aftercreditsstinger, based on novel or book, sequel — mixed with a handful of real mood words. This keeps however many genuinely describe the thing and throws the rest away. Not a fixed count: a title with one clear texture keeps one tag, a dense one keeps several, and an item whose tags are all trivia correctly keeps none.

The whole scraped tag list goes out with the description, and the model writes the rewrite first and then keeps the tags that agree with the reading it just committed to — so the same judgement about how a title feels drives both, and a tag that pulls against the summary gets dropped. Deciding them separately is what gives you a summary calling something quietly devastating next to a tag list saying "action". Done in one model call, so turning this on costs a single pass over the items without consolidated tags yet — not a full redo.
Off by default, and the reason is consistency rather than quality: a tag is only worth something if the same tag means the same thing across items, and free coinage produces near-synonyms — melancholy, melancholic, wistful, quietly sad — describing four films as four textures instead of one. The scraped list is a shared vocabulary imposed for free. Turn this on when you would rather lose that than lose a texture the metadata provider had no word for; the prompt constrains coinage to a last resort and to the plainest wording that fits, so two items with the same feel land on the same word.
A ceiling, not a target — most items should come back with fewer.
A separate decision from building them, and the useful order is to build first, look at what came back below, and only then start paying prompt tokens for them. This overrides Tags per item on the Library tab, which governs the raw scraped list.

When Curator runs

How often each of Curator's scheduled tasks fires. These are the same schedules as Dashboard → Scheduled Tasks — editing here changes them there and the other way round. Saving replaces a task's triggers, so if you set something more elaborate in Jellyfin's own page, that is what this will overwrite.

Generate Categories is the only task that always costs money. Condensing is cheap after the first pass, and cleanup and the health check are free, so those can run often. Refresh Recommendations is free too unless you have switched on model-ranked ordering, which spends one call per viewer every time it fires — check its cadence below if you have.
